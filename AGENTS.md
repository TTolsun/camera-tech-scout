# Repository Guidelines

## Project Structure & Module Organization

- `pipeline/src/scout/` contains the Python CLI, collection, evidence extraction, scouting, criticism, SQLite storage, and JSON export stages. `lexicon/` defines matching vocabulary; `engine/` contains optional LLM integration.
- `pipeline/tests/` contains pytest unit and golden pipeline tests. Offline repositories are generated by `pipeline/src/scout/fixtures.py`.
- `site/src/` contains Astro `pages/`, reusable `components/`, `layouts/`, shared `styles/`, and the TypeScript data loader in `lib/data.ts`.
- `config/sources.yaml` controls scan targets and budgets. Generated `data/*.json` feeds the site. `.github/workflows/` and `scripts/run-weekly.sh` automate validation and scanning.

## Build, Test, and Development Commands

Use Python 3.11+ and Git; CI uses Python 3.12 and Node.js 22. Run commands from the repository root unless specified.

- `python -m pip install -r pipeline/requirements-dev.txt`: install pipeline and test dependencies.
- Set `PYTHONPATH` to `pipeline/src`: `$env:PYTHONPATH = 'pipeline/src'` in PowerShell or `export PYTHONPATH=pipeline/src` in Bash.
- `python -m scout check-config`: validate scan configuration.
- `python -m scout scan --fixture --dry-run --no-llm --fail-on-empty`: run offline validation, writing JSON to `data-dryrun/`.
- From `pipeline/`, run `python -m pytest`: execute the test suite.
- `npm --prefix site ci`: install locked site dependencies.
- `npm --prefix site run dev`: start the development server.
- `npm --prefix site run build`: generate `site/dist/`; `npm --prefix site run preview` serves it locally.

## Coding Style & Naming Conventions

Use four-space Python indentation, type annotations, `snake_case` functions/modules, and `PascalCase` classes. Match existing two-space Astro/TypeScript indentation, single-quoted imports, and `PascalCase.astro` component names. Preserve LF endings per `.gitattributes`. No dedicated formatter or linter is configured. Follow `DESIGN.md` for visual changes; keep Korean display labels in `labels.py`.

## Testing Guidelines

Name pytest files `test_*.py` and functions `test_*`. Prefer deterministic fixtures and temporary directories over live APIs. Add regression coverage for analysis changes; explain intentional golden-expectation updates. No coverage percentage is enforced. Run tests, the fixture scan, and site build before submitting; CI also requires at least ten generated HTML pages.

## Commit & Pull Request Guidelines

Follow existing prefixes such as `feat:`, `test:`, `ci:`, and `chore:`. Describe behavior changes, validation results, and relevant issues (`Closes #N`) in PRs; include screenshots for UI changes.

## Evidence & Configuration Rules

Ground claims in collected evidence; preserve uncertainty markers and rejected candidates. Keep credentials in environment variables. Avoid incidental changes to generated `data/` or tracked `.cache/candidates.sqlite3`; use dry runs for development.
